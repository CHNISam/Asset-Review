# 美术资产管理规范

OpenCrit 管评审与交付依据，项目仓库／素材目录保存文件。工作项在 `backlog/tasks/`，不把素材目录变成另一套任务系统。当前支持图片与视频；音频延期。

## 最小流程

1. 在所属项目写清资产用途、需要的配置／视图和验收要求，再登记到 OpenCrit。已有成熟资产优先复用。
2. 交付设计稿，Owner 选用并确认整套设计。Agent 从 `asset-viewer prod lock <key>` 读取定稿；只有 `locked` 和 `verified` 都为 true 才能作为制作依据。
3. 按资产需要提交建模、UV、材质、绑定动画等证据。2D／UI 不强制走 3D 阶段；来源和授权记录附到适用阶段的 `source` 证据或项目文件。
4. 提交实机截图／视频和检查结果，由 Owner 验收。设计获批、文件可导入、实机效果通过是三个不同判断。

## 什么才是版本

| 对象 | 含义 | 处理 |
| --- | --- | --- |
| 资产 | 需要交付的一件东西，如角色、琴房、操作面板 | 一个稳定 key，注明项目与用途 |
| 配置变体 | 同时存在的配置，如钢琴键布局／圆形键布局 | `--variant`，互不替代 |
| 视图 | 正面／侧面／主界面等检查位置 | `--view`，每个槽独立迭代 |
| 版本 | 同一槽的前后修改 | 明确 `vN`，不按上传顺序猜测 |
| 同版预览 | 同一版的额外角度、状态、截图或视频 | `--preview-of N`，不新建版本 |
| 备选方案 | 竞争方向，最终选一个 | `--option`，不冒充前后版本 |

推荐路径（不强制搬迁已有素材）：

```text
<asset-key>/design/<slot>/v1/<primary>.png
<asset-key>/design/<slot>/v1/<preview>.png
<asset-key>/design/<slot>/v2/<primary>.png
<asset-key>/model/<evidence>.png
<asset-key>/engine/<capture>.mp4
```

不确定所属槽或版本的文件留在“待归类”。用 `prod move`／`prod detach` 修正错分，再运行 `prod audit <key>`；批准和定稿不能靠文件名推断。

## 交付与保留

- 下游使用定稿中列出的文件和 SHA-256，不自行抓“最新一张”。图片字节变化后需要重新确认；技术阶段 `ready` 只是待验收，Agent 不代替 Owner 批准。
- 外部素材至少记录来源链接、作者、许可及必要署名。生成素材在已知时记录工具／模型和生成批次。项目 MIT 许可不覆盖第三方美术；视觉批准不等于授权确认。
- 保留正式使用的素材、定稿和必要来源／授权记录。临时测试、多余转换文件、淘汰候选在 Owner 决定后清理，不永久囤积。
- 先用 `prod cleanup-plan` 查看计划，再由 Owner 在界面确认。现有清理将文件移入项目内回收目录，可恢复；它不释放磁盘空间。永久删除是单独的项目文件操作，不自动清空回收目录。选用中、定稿引用或证据引用的文件保留。

具体命令与 Agent 权限见 [AGENT_WORKFLOW.md](AGENT_WORKFLOW.md)。
